# Languages (English / Spanish)

**English** | [Español](./i18n.md)

Molde is published on GitHub. The landing page must be readable in both languages **from the first file**. The method (stories, specs, runbooks) stays in Spanish: that is the working language for the agent and the human in this repo.

## Switcher

One line at the top (after the H1 and badges). The language of **this** file is bold and not a link. The other language is a link. Fixed order: English | Español.

```md
**English** | [Español](./README.es.md)
```

```md
[English](./README.md) | **Español**
```

Do not add a second switcher. Do not use flags.

## Names

| What | File | Language |
| --- | --- | --- |
| Landing GitHub shows | `README.md` | English |
| Same landing | `README.es.md` | Spanish |
| Canonical method doc | `docs/…/name.md` | Spanish |
| Public mirror (when needed) | `docs/…/name.en.md` | English |

Do not create `docs/en/` or `docs/es/` (two trees). The `.en.md` suffix is the mirror.

## What is translated now

The landing (`README*`) and [what it is](que-es.en.md) / [qué es](que-es.md). The rest of `docs/` is born in Spanish. When a howto or a **door** page (clone, compare methods) becomes landing, add the `.en.md` in the same change.

## What is not translated

- Identifiers, paths, commands, file names (`AGENTS.md`, `STATUS.md`).
- Brand: **Molde**, **Clave**, **SDD**.
- Stories, specs, runbooks, ADRs, design kit, product `STATUS.md`.

## Agent

If the human writes in English, answer in English; the **source** you load is still the Spanish `.md`. The `.en.md` is a mirror, not a second brain. If only one half of a public pair exists, create the other or say it is missing.

Convention in `AGENTS.md`. Index: [howto README](README.md).
